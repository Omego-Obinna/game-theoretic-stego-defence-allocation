# Release checklist

This repository has been prepared locally, not uploaded or published.

- [ ] Confirm final manuscript title and sole-author citation (Obinna Omego).
- [ ] Confirm authority to distribute the new code under MIT, including any
      institutional or collaborator rights. Reused third-party archives are not
      covered by this permission.
- [ ] Confirm sharing permission for the saved derived records and figures and
      choose their reuse terms in LICENSE_SCOPE.md; no open-data licence is invented.
- [ ] Run the documented integrity, check and analysis commands in a clean checkout.
- [ ] Review the privacy exclusions, scientific limits and actual test report.
- [ ] Decide the reviewer-access route. This author-named public package is not
      anonymous. A private GitHub repository is not accessible to reviewers by
      URL alone; use an editor-approved supplementary or anonymised access route.
- [ ] Upload only github_repository/ contents, not submission_private/ or local
      reproduction working folders. Preserve hidden .gitignore and citation files.
- [ ] Create a tagged release after the author review. Do not assert a release
      URL, DOI or availability in the manuscript before it exists.
- [ ] Optionally archive the release with Zenodo (or another persistent repository),
      then record the real DOI, URL, version and release date in CITATION.cff.
- [ ] Update Data Availability and Code Availability statements with actual access
      details and explicit limits on access to the inherited image/gamma archive.
- [ ] Complete accurate AI-use, funding, conflict and authorship declarations.

If you edit files after preparation, the original CHECKSUMS.sha256 records the
prepared snapshot, not your new release. Preserve that snapshot and regenerate a
release checksum inventory with a documented change log; never use a new checksum
to imply that a modified numerical result is the original recorded result.
