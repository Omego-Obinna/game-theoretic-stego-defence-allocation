# Reproducibility

## Environment

Tested environment: CPython 3.12.3, NumPy 2.4.5, SciPy 1.17.1 and Matplotlib 3.10.9,
on Linux. The simulator and record-accounting checks use the standard library;
game solving needs NumPy/SciPy; numerical evaluations need NumPy; figures need
Matplotlib. No CUDA, PyTorch, LaTeX installation, or research plugin is required.
The recorded test environment is evidence of one working setup, not a claim of
testing every operating system or dependency combination.

## Safe commands

Run from the repository root after installing requirements.txt:

```bash
python tools/check_integrity.py
python tools/reproduce.py check
python tools/reproduce.py analysis
python tools/reproduce.py figures
```

Every command except the read-only integrity check creates a separate working
copy inside reproduced/. All historical analysis writes occur there. The exact
reference files remain under study/. Logs and a machine-readable run report are
retained in each working directory. Failed subprocesses stop the command.

### check

Runs the 35 transport tests, 15 game tests and 14 sensitivity-engine tests, then
the original independent game, validation and sensitivity verifiers and the
representative bootstrap-arithmetic verifier. The validation verifier includes
one bounded deterministic replay with a missing image. Unit tests use synthetic
bytes. This is verification, not a fresh-seed experiment or an embedding run.
Historical fingerprints remain checked, not disabled for packaging convenience.

### analysis

Recomputes development game solutions from the saved 3,960 pilot sessions;
recomputes validation and sensitivity estimates, including their bootstrap
intervals, from the saved raw records and original frozen policies. It does not
refreeze or refit policies against new outcomes. The wrapper compares regenerated
numerical JSON against the recorded reference with a 1e-10 absolute tolerance.
Original result fingerprints and any byte-exact equality are also reported.
Elapsed-time metadata are not required to reproduce byte-for-byte.

### figures

Runs both original plotting scripts against copied reference estimates. Figure
regeneration is separate from statistical evaluation. PDF timestamps, installed
fonts and Matplotlib details can prevent byte-identical PDF files even when the
plotted numerical values agree. The current manuscript uses the figure mapping
in docs/FIGURES.md, not the older combined results_supplement.pdf automatically
generated by the first plotting script.

## What is and is not reproducible here

The complete saved-outcome analysis, game fitting, frozen-policy evaluations and
plotting inputs are supplied. The atomic-object engines and their historical
runners are supplied as source, together with seeds and sampled record metadata.

The historical pilot.py, run_holdout.py and run_validation.py entry points also
read the original archive and a local evidence manifest. Those external inputs
are intentionally not included, and those commands are not the quick-start path.
Full re-extraction of source availability/flags and full-byte fixture validation
require authorized access to the original archive and path configuration. This
package does not claim independent replication of that inherited evidence.

The historical run_sensitivity.py can replay its model using included prior
samples, but deliberately refuses to overwrite existing results. A full new
simulation sweep is not performed by any documented quick-start command.
Do not remove its guard or delete recorded results to rerun until a preferred
answer is obtained. Preserve any independently authorized reproductions as
separate outputs.

## Scientific safeguards

Development seeds: 190901-190905. Validation seeds: 191001-191020; sensitivity
reuses these validation scenarios. Development and validation cover identifiers
are disjoint, but identifiers can recur across seeds. Payloads and endpoints
share observations. Counts therefore do not describe independent replications.

Policy mixtures are integrated before minimising over attack-specific means.
The code must not be changed to choose an attack separately after seeing the
realised pure policy. Coalition worths are reoptimised development quantities;
frozen-coalition transfer scores must not be relabelled as new worth functions.

No recorded manuscript result is changed by this packaging exercise.
